この制作環境のブラウザーはURLへの移動が管理ポリシーで制限されています。そのためブラウザー操作テストには、分離した本体から `build-preview.mjs` で生成した**同一ソースの自己完結HTML**を使い、Playwrightの `set_content` で読み込みました。ポリシー自体は変更していません。

一方、静的ファイルのHTTP配信は、別のNode.jsテストで実際にサーバーを起動して検証しています。つまり、配信とブラウザー描画はそれぞれ確認済みですが、この環境ではURL移動から描画までを一続きに通したブラウザーテストではありません。

合成音についてはAudioContextの開始、実行状態、出力ゲインの変化、停止を検証しました。ヘッドレス環境のため、スピーカーから出た音の聴感評価を実施したという意味ではありません。全画面表示はブラウザーや埋め込み側の許可に依存し、利用できない場合はUIで知らせます。

## 任意のブラウザーテストの再実行

Python環境にPlaywrightとそのChromiumが導入されている場合:

```text
python tests/browser.py
```

この検証用Pythonスクリプトは本体の動作には不要で、`npm test` からも呼びません。別のChromium実行ファイルを利用する場合は `FERRO_BROWSER_EXECUTABLE` を指定できます。ソフトウェアWebGLによる検証は `FERRO_SOFTWARE_GL=1`、必要な隔離CI環境でのみサンドボックスを外す場合は `FERRO_NO_SANDBOX=1` を使用します。Linuxの構成によってはXvfbなどのディスプレイ環境も必要です。

本体を変更した後は、コードの自動テストに加え、実際に利用するブラウザー・端末で見た目と操作を確認してください。
