# 構成と変更箇所

## データの流れ

```text
入力・ボタン
    ↓
app.js の状態（回転数／時間倍率／クランク角／表示モード）
    ↓
kinematics.js の共通計算
    ↓
engine.js の部品配置・回転・バルブリフト
    ↓
math.js のシーングラフと行列
    ↓
renderer.js の描画バッチ・金属・影・後処理
    ↓
WebGL2 canvas
```

角度の更新元は1つです。ピストン、コンロッド、クランク、カム、バルブごとに独立したアニメーション時間を作っていません。

## 機構

`kinematics.js` の表示単位で、クランク半径は `r = 0.60`、コンロッド長は `l = 1.92` です。クランク軸方向がX、上下方向がY、前後方向がZです。各シリンダーの位相を `θ` としたとき:

```text
クランクピン Z = r sin(θ)
クランクピン Y = r cos(θ)
ピストンピン Y = r cos(θ) + √(l² − r² sin²(θ))
コンロッド回転 = atan2(−クランクピンZ, ピストンピンY − クランクピンY)
```

この式から部品の位置と回転を決めるため、コンロッドの見た目の長さを伸縮させずに両端が接続します。テストでは実際のシーングラフのワールド座標でも端点一致を検証します。

1番シリンダーの燃焼上死点を0°とし、膨張→排気→吸気→圧縮の順で720°を一周します。気筒番号順の位相オフセットは0°・540°・180°・360°です。点火順序は1–3–4–2になります。

表示単位は `86 / 1.2 mm`。ボア半径0.60とクランク半径0.60で、86 × 86 mmの寸法を揃えています。バルブは左右14°、挟み角28°のペントルーフ配置です。バルブ・ガイド・バケット・スプリングを同じ傾斜座標系に置き、軸方向へリフトします。カム軸位置もシート位置、バケット上面、ベース円から求めます。

吸気は332–620°、排気は108–396°に開き、吸排気上死点でオーバーラップします。最大リフトは吸気0.115（約8.24 mm）、排気0.105（約7.53 mm）。中央の余弦リフトに滑らかな着座ランプをつなぎ、着座時の変位・速度・加速度を0にしています。これらは独自の固定設定で、特定車種の実測カムや可変バルブタイミングの再現ではありません。

カム断面はフラットバケットとの接触包絡線です。接触法線を `n`、接線を `t`、支持距離を `h = base + lift` として `p = h n + h' t` で輪郭を作ります。傾斜角と気筒位相を含め、クランクとカムの2:1の関係を適用します。384分割の滑らかな法線とベベルを使い、`h + h'' > 0`、接触点がバケット内にあること、実メッシュとバケット面の接触を検証しています。

スプリングは頂点シェーダーでピッチを変え、線材の半径0.02を保ちます。影にも同じ変形を使います。更新ごとに形状バッファを作り直したり、線材ごと縦に潰したりしません。6巻きの密着長、バルブとピストンの隙間、45 g・予圧180 N・線径・コイル径・巻数と鋼のせん断弾性率79 GPaから求めるばね定数（約19.3 N/mm）という仮定での接触力を検証しています。これは指定条件での幾何・準静的な検証で、弾性振動や実機のバルブフロートを解く動力学計算ではありません。

チェーンの移動量はリンクピッチと1回転20歯に対応させています。ただし、張力・弛み・ローラー接触の動力学を解くものではありません。

## 点火・燃料噴射・吸排気

`K.ignitionAt(phase, rpm)` は圧縮上死点前10–32°の進角と1.2 msの放電を返します。回転数を上げると放電が占めるクランク角も増えます。再生倍率は実時間を伸縮するだけで、点火順序と機構の位相を変えません。放電は中心電極と接地電極の0.9 mmの隙間につながる赤い主放電線と、接地電極へ終端する細い分岐で描きます。5種類の経路を放電時間内に切り替え、線の発光・経路に沿う残光・近傍金属への赤い照り返しを分離しています。

`K.combustionAt(phase, rpm)` は放電開始から0.15 ms後に燃焼を開始し、規定したWiebe型の燃焼進行度を返します。火炎核はプラグの電極間から成長し、凹凸を持つ火炎面と高温の既燃ガスをボリュームとして描きます。火炎面は上死点後約45–49°で消え、その後はピストンの下降に合わせてガスを伸長し、体積増加に応じて密度と発光を減衰させます。これはクランク角に同期する可視化用の規定モデルです。圧力、反応化学、流動、熱収支、トルクとの連成を数値解析するものではありません。

燃焼の描画は視線とボア・ピストン上面・左右の傾斜天井との交区間で光を積算します。不透明部品の深度を別のテクスチャへコピーして積算の終端に使うため、手前のピストンやバルブがガスを遮ります。内壁とピストンには燃焼の進行に同期した暖色の照明を加えます。LOW／STD／HIGHの積算数は24／40／56です。火炎の形状とノイズの時間もクランク角から求めるため、一時停止と逆方向の角度操作で状態を再現できます。

インテークはスロットル／プレナム／4本のランナー／各気筒2本のポートへ接続します。燃料レールに接続する4本のインジェクターを吸気ポートに配置し、各2方向の噴霧を吸気バルブへ向けます。`K.injectionAt` は380°から3.0 msの吸気同期噴射を開始します。飛行時間2.4 msを持つ噴霧の先端と後端を追い、噴射停止後も既に出た燃料が移動します。霧の濃度はコーン内の光路をサンプリングして描き、粒子の直径は約79 µmです。流量、燃料質量、気化、空燃比、壁面液膜は解いていません。

各ヘッドポートは `G.branchedPipe` で共通の入口と2つの出口を一体で生成します。分岐位置で入口の左右の半円形断面を、それぞれの円形ポートへ連続的につなぎます。内壁・外壁・分岐先端を持ち、共通入口の内側に別の管壁を重ねません。断面表示では同じ切断面を全体に適用し、切断端は管壁の厚みだけをふさぎます。形状は気筒間で共有します。

ヘッドの後側の支柱は気筒間に配置します。入口、両噴射コーン、断面で見える支柱・周辺部品について、実際の三角形との交差を検査し、流路を横切る部品がないことを確認します。

エキゾーストは1/4番、2/3番を組にする4–2–1の流路です。中空管、肉厚、フランジ、溶接部、集合管、酸素センサーを持ちます。管の形状は流路の可視化であり、製造用の水密CADや排気脈動のCFDモデルではありません。

断面表示でも両マニホールドと燃料系は残し、管壁の一部を切り開きます。外観表示では壁を閉じ、分解表示では部品を離します。点火・噴霧・燃焼は、組み付け位置に戻った断面表示でのみ有効です。燃焼・噴射スイッチで一括停止します。「点火」「燃焼」「燃料噴射」は該当位相へ停止し、接写位置へ移ります。「燃焼」は1番気筒の上死点後24°に合わせます。再生を押すと、その観察位置から動きを追えます。

### 構造を確認した一次資料

- [Bosch: Gasoline port fuel injection](https://www.bosch-mobility.com/en/solutions/powertrain/gasoline/gasoline-port-fuel-injection/) — 吸気バルブ手前での混合気形成、燃料レール、吸気同期噴射の構成。
- [DENSO: Spark Plugs Manual](https://assets.denso-am.eu/production/attachments/Spark-Plug-Manual-English_v2.pdf) — 第2・3・6章。圧縮上死点前の点火、ミリ秒単位の放電、電極間からの火炎核成長。
- [NGK: プラグの着火性能](https://www.ngk-sparkplugs.jp/ngk/sparkplugs/basic/qa/000013.html) — 放電から混合気へ着火する仕組み。

資料は構造と現象の確認に使用しています。上記の寸法・固定タイミングはこのプロジェクトの設計値であり、メーカーの推奨値や実測値を意味しません。

## 描画

3Dの `viewport` は表示モードや画面幅によらず `observatory` 全体を覆います。文字・観察ボタン・操作パネルは前面へ重ね、操作パネルと部品解説などの背景だけを半透明にします。文字のレイヤーはポインター操作を通し、ボタンやパネルの操作は前面で受け取ります。観察ボタンは3D領域と同じ親の要素とし、接写・探索・レスポンシブ切り替えではUIの位置を調整します。

`geometry.js` は回転体、ベベル付き箱、リング、チューブ、スプリング、歯車、カムなどを作ります。`engine.js` は同じ形状をキャッシュし、ボルトなどの反復部品で再利用します。

`renderer.js` は形状IDとマテリアルIDごとに部品をまとめてインスタンス描画します。描画順は、光源側の深度、金属などの不透明面、ガスなどの透明面、画面空間の陰影と仕上げです。

反射用のスタジオ照明はシェーダー内の解析的な形状から作ります。外部のHDRファイルを読み込む方式ではありません。光源の映り込みとGGX型の反射を使っていますが、パストレーシングや実測材質データによる校正済み描画ではありません。

STD/HIGHでは対応する範囲でマルチサンプル描画を使い、色・法線・深度を解決してから後処理を行います。LOWでは影の解像度を下げ、画面空間の陰影とマルチサンプルを省きます。

## よく変更する場所

| 変更 | 場所 |
| --- | --- |
| 背景・色・文字・レイアウト | `css/style.css` |
| 見出し・UIの固定文言 | `index.html` |
| 初期回転数・速度・品質 | `js/app.js` の初期状態と初期設定 |
| 初期カメラ・視点リセット | `js/app.js` の `CameraController` |
| 部品説明 | `js/app.js` の `PARTS` |
| 機構の寸法・位相・行程 | `js/kinematics.js` |
| 外観形状・材質・分解距離 | `js/engine.js` |
| 光・反射・影の品質 | `js/renderer.js` |
| 合成エンジン音 | `js/audio.js` |

機構寸法を変更するときは、形状側の寸法との対応も調整してください。共通計算だけを変更しても、外装やピストンなどの形状が自動的に再設計される仕組みではありません。

## 開発用の観察窓

`window.ferro` から現在の状態と診断情報を確認できます。これは開発・検証用で、安定した外部公開APIではありません。

```js
ferro.getDiagnostics();
ferro.setMode('cutaway');
ferro.setAngle(180);        // 手動角度。再生は停止する
ferro.setRPM(1200);
ferro.setSpeed(0.025);      // 鑑賞速度 1/40
ferro.setRunning(true);
```

`getDiagnostics()` の部品数は、そのフレームで表示されているメッシュ要素の数です。材料や工程としての実部品の点数を証明する数値ではありません。
